# 🇬🇧 English

## Project Overview

Urban Scooter is a scooter rental platform. This QA training project involved testing its web application, Android mobile application, REST APIs, and related database functionality.

The objective was to evaluate functional requirements, identify defects, and document test results.

## Tools and Technologies

- Manual Testing
- Test Case Design
- Equivalence Partitioning
- Boundary Value Analysis
- Postman and REST APIs
- HTTP and JSON
- SQL
- Android Studio Emulator
- Jira
- Bug Reporting

## Testing Activities

### 1. Requirements Analysis
- Reviewed functional requirements.
- Created functional diagrams.
- Identified ambiguous requirements and areas requiring clarification.

### 2. Test Design
- Designed equivalence classes and boundary values.
- Prepared positive and negative test scenarios.
- Documented expected results.

### 3. Mobile Application Testing
- Documented and executed 46 test cases.
- 31 passed.
- 15 failed.
- Tested order management, notifications, and application behavior.

### 4. API Testing
- Recorded 173 checks with execution status.
- 133 passed.
- 40 failed.
- Validated HTTP responses, JSON data, input validation, and business rules.

These figures represent recorded checks, not necessarily independent test cases.

### 5. Defect Reporting
- Documented defects discovered during testing.
- Recorded reproduction steps, expected results, actual results, and severity.
- Linked failed tests to Jira bug reports.

## Project Structure

- `requirements-analysis/` — Requirements and functional diagrams
- `test-design/` — Equivalence classes and boundary values
- `mobile-testing/` — Android test cases
- `api-testing/` — REST API testing
- `bug-reports/` — Defect documentation
- `test-results/` — Test execution summaries

# 🇨🇴 Español

## Descripción del proyecto

Urban Scooter es una plataforma de alquiler de scooters. Este proyecto práctico de formación en QA incluyó pruebas de su aplicación web, aplicación móvil Android, servicios API REST y funcionalidades relacionadas con bases de datos.

El objetivo fue evaluar requisitos funcionales, identificar defectos y documentar los resultados de las pruebas.

## Herramientas y tecnologías

- Pruebas manuales
- Diseño de casos de prueba
- Clases de equivalencia
- Análisis de valores límite
- Postman y API REST
- HTTP y JSON
- SQL
- Android Studio Emulator
- Jira
- Documentación de defectos

## Actividades realizadas

### 1. Análisis de requisitos
- Revisión de requisitos funcionales.
- Elaboración de diagramas funcionales.
- Identificación de requisitos ambiguos y zonas grises.

### 2. Diseño de pruebas
- Diseño de clases de equivalencia y valores límite.
- Preparación de escenarios positivos y negativos.
- Documentación de resultados esperados.

### 3. Pruebas de aplicación móvil
- 46 casos de prueba documentados y ejecutados.
- 31 casos aprobados.
- 15 casos no aprobados.
- Validación de gestión de pedidos, notificaciones y comportamiento de la aplicación.

### 4. Pruebas de API
- 173 comprobaciones con estado registrado.
- 133 comprobaciones aprobadas.
- 40 comprobaciones no aprobadas.
- Validación de respuestas HTTP, datos JSON, entradas y reglas de negocio.

Estas cifras corresponden a comprobaciones registradas y no necesariamente a casos independientes.

### 5. Documentación de defectos
- Registro de defectos identificados durante las pruebas.
- Documentación de pasos de reproducción, resultados esperados, resultados reales y severidad.
- Vinculación de pruebas fallidas con reportes de Jira.

## Estructura del repositorio

- `requirements-analysis/` — Requisitos y diagramas
- `test-design/` — Diseño de pruebas
- `mobile-testing/` — Pruebas móviles
- `api-testing/` — Pruebas de API REST
- `bug-reports/` — Informes de defectos
- `test-results/` — Resultados de ejecución
