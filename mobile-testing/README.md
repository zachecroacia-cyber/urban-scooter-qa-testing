# Mobile Testing | Pruebas Móviles

## English

### Project Overview

Android mobile application testing performed as part of the Urban Scooter QA training project at TripleTen.

The testing focused on validating functional behavior, user interface elements, order management, and application usability.

### Testing Environment

- Application: Urban Scooter (Android)
- Test device: Samsung Galaxy S20 Ultra
- Operating system: Android 13
- Testing tools: Android Studio Emulator and manual testing techniques

### Testing Scope

- Functional testing of the Android application.
- Order list and order acceptance workflows.
- User interface and visual validation against Figma designs.
- Field and screen behavior verification.
- Positive and negative test scenarios.
- Defect identification and documentation in Jira.

### Test Execution Results

According to the test execution workbook:

- Passed: 31
- Failed: 15
- Total: 46

These figures represent recorded test outcomes, not unique defects.

### Documented Defect: KAN-18

**Title:** Accept button overlaps the metro station name on collapsed order cards.

**Severity:** Minor

**Description:** On the All Orders screen, long metro station names such as 7th Street/Metro Center are partially obscured by the Accept button when order cards are collapsed.

[View KAN-18 bug report](https://github.com/zachecroacia-cyber/urban-scooter-qa-testing/blob/main/bug-reports/KAN-18.md)

## Español

### Descripción del proyecto

Pruebas de la aplicación móvil Android Urban Scooter realizadas como parte del proyecto de formación QA en TripleTen.

Las pruebas se enfocaron en validar el comportamiento funcional, los elementos de interfaz, la gestión de pedidos y la usabilidad de la aplicación.

### Entorno de pruebas

- Aplicación: Urban Scooter (Android)
- Dispositivo de prueba: Samsung Galaxy S20 Ultra
- Sistema operativo: Android 13
- Herramientas: Android Studio Emulator y técnicas de pruebas manuales

### Alcance de las pruebas

- Pruebas funcionales de la aplicación Android.
- Listado y aceptación de pedidos.
- Validación visual de la interfaz frente a diseños de Figma.
- Verificación del comportamiento de pantallas y campos.
- Escenarios positivos y negativos.
- Identificación y documentación de defectos en Jira.

### Resultados de ejecución

Según el archivo de ejecución de pruebas:

- Aprobadas: 31
- No aprobadas: 15
- Total: 46

Estas cifras corresponden a resultados de pruebas registrados, no a defectos únicos.

### Defecto documentado: KAN-18

**Título:** El botón Aceptar se superpone al nombre de la estación de metro en las tarjetas contraídas.

**Severidad:** Menor

**Descripción:** En la pantalla Todos los pedidos, los nombres largos de estaciones de metro, como 7th Street/Metro Center, quedan parcialmente ocultos por el botón Aceptar cuando las tarjetas están contraídas.
